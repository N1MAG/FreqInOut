JJS | 05-25-23 (Supersedes PGP/GPG Guidance Document dated 05/21/23)
This document Supersedes PGP-GPG Signature Verification - General
Guidance Document dated, 05/21/23
Upon further investigation and discussion, we have discovered the GUI
(Graphic User Interface) Kleopatra is now superior to GPA (GnuPG Privacy
Assistant) recommended in the previous guidance document. Kleopatra
accomodates the more advanced ECC (Eliptical Curve) GPG keys.
Eliptical Curve keys are MORE SECURE and use SMALLER KEY SIZES
Purpose: To provide guidance for the use of Gnu Privacy Guard with
Kleopatra for verifying the authenticity of files and folders sent over radio.
Objective: To answer the questions for stations receiving traffic from
AmRRON, “Is this really from AmRRON?” and “How can I be sure the
sending callsign hasn’t been ‘spoofed’?”
Action Items:
Download and install GnuPG: https://gnupg.org/download/index.html
● Windows users: On the Download page at gnupg.org, scroll down
and select GPG4WIN.
● Linux users: GnuPG comes with Linux already. All you need to do is
install Kleopatra.
Open a command terminal (Ctl+Alt+T) and enter the following
command:
sudo apt install kleopatra
_______________________________________________________________
NOW is the time to establish this authentications system, while the internet
is up and we can verify each other’s identities through email, via the
website, or other secure methods. Exchanging keys over the radio AFTER a
grid down situation cannot be considered secure without previously
coordinated COMSEC protocols.
NOTE: The terms GPG and PGP are used interchangeably for the purposes of
this document.
NOTE: The FCC has commented, and the use of PGP/GPG keys for signing
files for authenticity is perfectly legal and acceptable, and does not violate
Part 97 rules on encryption. One is not obscuring the true meaning of the
traffic. One is simply attaching a certificate which only his/her password can
be used to produce a verified certificate for the file being sent (or for
verification when receiving from another).

IMPORTING KEYS FROM AmRRON (and others)
The new AmRRON Actual eliptical curve key is named:
AmRRON_Actual_ECC_PUBLIC.asc
If the key you have does not include ‘ECC’ in the file name, it is not the
most current key. It can be downloaded from:
https://amrron.com/wp-
content/uploads/2023/02/AmRRON_Actual_ECC_PUBLIC.asc
Fingerprint: 77F8 88F3 524F 00C7 5FF9 F91A 8D51 8D7A 5061 2239
WHEN YOU IMPORT A KEY FROM ANOTHER PERSON, you may
need to ‘Certify’ (digitally sign their key), or you may get a failure to verify
when attempting to authenticate files from them.
TO CERTIFY A KEY, simply right click on their key in the list of keys you’ve
imported in Kleopatra, and select ‘Certify’.
A dialog box will pop up. Click the button to the left of their key.
Select your key that you wish to use to certify their key, and then select
‘Certify only for myself’.
Do not select the certification for everyone to see, and especially DO NOT
select ‘Send certified certificate to server’.

If the result is a ‘Bad’ verification:
1. You have not imported and/or ‘signed’ the key of the original certificate

2. The original file (example AIB.k2s) has been altered or was corrupted

Which traffic will be digitally signed?:
When ‘official’ AmRRON traffic is transmitted, or traffic sent by Digital HF
NCSs involving spectacular events or information (plane crash with
hundreds of casualties, nuclear detonation, foreign troops spotted, etc.) be
sure to digitally sign the documents and include it in all *Forward Error
Correcting (FEC) and ARQ transmissions so it can be authenticated by
recipients. This includes:
FLAMP Winlink Pactor vARIM gARIM Etc...

ONE-FILE CERTIFICATION
If you receive a single file (for example: the weekly AIB), and do not see a
seperate .sig certificiate, LOOK FOR ‘-sig.k2s’.
In this example, the AIB is signed inside
the document, as you will see if you open
in a text editor/reader.
- It will open and look the same as any
other FLMSG form when opened in FLMSG
- It will verify the key in Kleopatra, the
same as a .sig certificate
This keeps the signature and the file being verified all within a single file, so
avoids the need to send both, the AIB plus a .sig certificate.

wordpad, etc.), copy/paste the text from your document, such as the AIB,

just like any other .k2s file, dropping the PGP signature portion from the
opened file (SITREP, SPOTREP, Blank form, AIB, etc.).

PGP signed certificates, when available, SHOULD accompany official
AmRRON traffic, such as the weekly AIB, or SITREPS and Executive
Summaries from the SIGCENs. However, if you have traffic to pass (such as
the AIB), but do not have a digitally signed certificate, pass the traffic
anyway UNLESS you suspect it to be malicious, false, or otherwise impostor
traffic. Try to verify with other stations you normally work with to determine
if they may have been able to authenticate the traffic. The file could have
been just fine, but became corrupted between you and the station sending
it to you.
It is NOT necessary to digitally sign all traffic, such as the Supplemental
Vericode, or benign traffic, such as ‘Thunderstorms and flooding in my area’
or ‘Power and internet down in my area’.
