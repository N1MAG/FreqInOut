FreqInOut User Guide

Current version: 1.1.4

This guide describes every tab, button, field, and function in FreqInOut. Times are stored in UTC; the "Showing: Local/UTC" toggle only changes what you see.

Responsibility notice: FreqInOut assists licensed amateur operators by coordinating complex radio software and schedules. It assumes you follow applicable band plans and regulations. Disabling safeguards (for example, scheduling) can let you tune outside legal allocations. You are solely responsible for compliant operation; the authors and contributors are not liable for misuse.

Quick Start

Purpose: Get a first successful setup and first on-air workflow quickly.

  1. Start in Settings: Open Settings and enter your callsign/name/state/grid, choose Frequency Control mode, set JS8Call DIRECTED.TXT (if using JS8 features), and set message folders. Click Save Settings so all tabs refresh with your configuration.
  2. Choose your operating mode: FreqInOut supports (a) JS8Call-only operation, or (b) FLRig/FLDigi operation (with optional JS8Call/VarAC). VarAC is supported as an integration, but VarAC-only is not a supported standalone control mode.
  3. If using FLRig as rig control: In JS8Call set Rig to FLRig. In VarAC, open Rig Settings, set CAT control and Frequency Control to FLRig, and keep periodic frequency reads enabled.
  4. FLDigi monitoring: To monitor if FLDigi is receiving traffic, you must enable logging in FLDigi under File > Text Capture > Log all RX/TX text.
  5. Create Operating Groups: Add your go-to frequencies in Operating Groups. These drive HF Schedule, Net Schedule, QSY controls, SOP filters, and scheduler enforcement targets.
  6. Build schedules: Use HF Schedule for routine blocks and Net Schedule for net windows (including early check-in). Confirm layout in FreqPlanner.
  7. Load operators and traffic context: Import your list in Operators. For JS8 workflows, go to Settings > JS8Call Settings and run Load JS8 Traffic to seed map/link history.
  8. Run your first cycle: QSY to an Operating Group, verify Schedule Status, start/monitor a net from FLDigi NCS or JS8 NCS, then review outcomes in Messages, Operators, and Map.

New Operator Onboarding (First Session)

Purpose: Give new HF users a safe, practical path from install to first successful operating cycle.

  1. Set identity and save: In Settings > Operator Information, enter Callsign/Name/State/Grid and click Save Settings.
  2. Choose simple control mode: In Settings > FreqInOut Settings, start with Manual if you are unsure, then move to FLRig or JS8Call control after validation.
  3. Add one Operating Group: In Settings > Operating Groups, add one known-good frequency/mode row you can monitor on-air safely.
  4. Build one HF schedule row: In HF Schedule, add one row for current day/time and save. Verify it appears in FreqPlanner.
  5. Test QSY behavior: From HF Schedule or NCS tab, use QSY once and confirm Schedule Status reflects pause/resume behavior.
  6. Load operator context: In Operators, import CSV if available; otherwise continue with manual additions as contacts are observed.
  7. Run one controlled net session: Use FLDigi NCS or JS8 NCS, start a test net, record at least one check-in, save, and end cleanly.
  8. Review outputs: Confirm results in Operators, Messages, Map, and Logs. Keep logs at INFO or DISABLED for routine use.
Tip for first day: keep schedules simple (one or two rows), avoid aggressive automation, and confirm each integration path one at a time.

Advanced Operator Workflow (Daily Ops)

Purpose: Fast reference for experienced operators running recurring schedules, nets, and SOP reminders.

  1. Pre-op check (2-3 min): Verify Schedule Status is on-plan, validate rig/software status LEDs in Settings, and confirm current band/frequency alignment.
  2. Sync schedule intent: Review FreqPlanner for today’s windows; ensure Net Schedule rows include proper recurrence + early-check-in values.
  3. Run SOP alongside schedule: In SOP, keep active SOPs scoped by operating group/sub-group and monitor only actionable rows (Due Now/Overdue).
  4. Manage net execution: Use NCS tabs for net lifecycle (start, acknowledge/query, save, end). Use QSY intentionally and resume scheduler when appropriate.
  5. Use filters aggressively: In Messages/Operators/Map/Peer Schedules, filter by time/group/region/status before making decisions to reduce cognitive load.
  6. Post-op hygiene: Clear stale prompts, reconcile operator roles/trust flags, export needed data, and return logging level to normal.

First-Run Readiness

Purpose: Confirm in-app configuration is complete before operating.

  • Callsign identity: Set Callsign/Name/State/Grid in Settings. This affects NCS actions, exports, map placement, and operator matching.
  • Frequency control selection: Choose FLRig, JS8Call, or Manual in Settings based on your station topology.
  • Core paths: Set JS8Call DIRECTED.TXT (if using JS8), message paths (FLMSG/FLAMP/VarAC), and FLDigi log folder (if using scheduler busy detection with FLDigi).
  • Operating Groups baseline: Add at least one valid group row (mode, band, frequency, VFO/offset as applicable).
  • Scheduler intent: Decide whether to run with scheduler enabled or manual control before going on-air.

Main Window and Navigation

Purpose: Understand the sidebar, global UI behavior, and system prompts.

Typical workflow: Watch this panel first. It is your real-time "am I on plan?" indicator, your nearest remediation path (Resume Schedule), and your earliest warning when operator action is required.

Expected UI behavior:

  • Sidebar labels: Tab labels append your callsign after saving valid operator identity settings.
  • Map filters visibility: Map Layers controls appear only while Map tab is active.
  • Status panel updates: Schedule Status updates continuously and reflects suspend/off-schedule/net/busy conditions in near real time.
  • Resume control authority: Clicking Resume Schedule clears pause/skip state and reapplies schedule targets immediately when allowed.
  • Sidebar navigation: Click a left-side button to switch tabs. After saving a callsign in Settings, each tab label becomes Tab [CALLSIGN].
  • Logs indicator: If the log level is not DISABLED, the sidebar label changes to Logs Enabled and is highlighted in a warning color.
  • Map Layers sidebar: Only visible while the Map tab is active. Controls Callsigns, States, Cities, Grids, Regions, and City Pop. filtering.
  • Schedule Status panel: Below the tab buttons (hidden on Map), shows On Schedule / Off Schedule with specific reasons (e.g., Frequency, FLDigi Mode, JS8 Offset, QSO traffic, or Sending Traffic when PTT is active). When scheduling is disabled or Frequency Control is Manual, it shows the current frequency only. Includes a blue Resume Schedule button that immediately applies the schedule and overrides any prior Skip/Pause state. When an SOP reminder is coming within 3 hours, the header shows SOP Action in: H:MM. When JS8/VarAC/FLDigi have recent RX activity, an informational BUSY RX: ... line appears; it is hidden during nets. FLDigi may display as FLDigi (gibberish) when noisy RX is detected.
  • Off-schedule prompt: When a configured enforcement item first goes off schedule, a dialog appears listing only those items (e.g., Frequency and Offset are Off Schedule) with buttons Resume Sched., Skip Once, and Pause Sched. 30 Min. Resume Sched. enforces only the listed items; Pause Sched. 30 Min pauses enforcement for 30 minutes; Skip Once resets the prompt timer. If you do not respond within 2 minutes, the listed items are applied automatically. Repeat prompts follow the selected prompt interval.

Important background timers:

  • Scheduler evaluation loop: Runs continuously and updates active entry / next-change state.
  • Prompt auto-apply: Off-schedule prompts auto-apply listed corrections after 2 minutes if ignored.
  • SOP status horizon: Status panel shows SOP countdown only when an SOP action is within 3 hours.
  • BUSY RX windows: Recent RX/PTT windows can temporarily defer schedule corrections to avoid disrupting traffic.

FreqPlanner Tab

Purpose: A read-only 24-hour view of HF and Net schedules.

Typical workflow: Use this as the "source-of-truth view" after each schedule edit. If something looks wrong here, fix HF/Net schedule entries before operating.

Expected UI behavior:

  • Read-only planner: Cells cannot be edited directly and are not sortable.
  • Display toggles only: UTC/Local and Band/Frequency toggles change display text only, not stored schedule data.
  • Band color persistence: Band chip color changes persist across sessions.
  1. Header clocks: UTC and Local times update live.
  2. Showing: UTC/Local: Toggle how the time columns are labeled; schedule data is still stored in UTC.
  3. Showing Band / Showing Frequency: Toggles the cell text between band labels and frequency values (3-decimal MHz). Net entries still show the net name alongside their band.
  4. Band colors chips: The legend row shows chips only for bands present in the current table. Clicking a chip opens a color picker; the dialog includes a Reset Default button for that band. Colors persist and apply to band labels in the grid.
  5. Planner table: Columns are UTC Hour, Local Time (TZ), and Sunday through Saturday. The table is read-only and not sortable.
  6. Highlighting: The current UTC day column is highlighted for hours that include net entries.

SOP Tab

Purpose: Build reminder-only SOP action plans per operating group.

Typical workflow: Select Operating Group and optional Secondary Group, set SOP Daily Start, add action rows, save, then monitor the Status column during operations to complete actions on time.

Expected UI behavior:

  • Manual completion model: Actions never auto-complete; operator action marks completion.
  • Status windows: Due timing transitions should display Due Now, then Overdue, then hide stale actions based on configured aging rules.
  • Save-state cue: Save button highlights only when SOP configuration changes exist.
  • Mismatch signaling: Band/Frequency mismatch against schedule appears as warning-highlighted cell with tooltip.
  1. Builder model: Build each SOP one row at a time with Band, Frequency, Software, Action, Interval, Contact Rule, Contact Target, and Description.
  2. SOP Daily Start (TZ): A master start time anchors all action cadence. The label and displayed value follow the current UTC/Local toggle.
  3. Interval (HH:MM): Enter intervals as HH:MM (for example, 00:30, 01:00, 06:00). The field supports typed values for granular recurrence.
  4. Timezone display: SOP uses header clocks and the Showing UTC/Showing Local toggle. Data is stored in UTC.
  5. Contact rules: Rule options are filtered by roles available for the selected Operating Group (+ Secondary Group when used). Role options include HUB/HUB-ALT, NCS/ANCS, PEER, and CallSign targeting.
  6. Contact target: Target is type-ahead searchable. Use Any (Role Match) or select a specific callsign based on the selected contact rule.
  7. Status button behavior: The Status button text reflects reminder state. Due Now (0-20 min, info), Overdue (20-30 min, warning), Completed (success).
  8. Action visibility: Actions older than 30 minutes past due are hidden to keep the reminder list focused.
  9. Scheduling mismatch: If SOP and schedule alignment differ, the Band/Freq cell is highlighted with a warning and tooltip Scheduling Mismatch.
  10. Save highlighting: Save highlights only when SOP configuration changes are made.
  11. Import/export: SOP profiles export/import as JSON; actions for unconfigured software are preserved for later use.

Messages Tab

Purpose: View and manage FLDigi/FLMsg/FLAmp/VarAC files and JS8 inbox messages.

Typical workflow: Filter first, open/read second, then flag or delete. Use Pending JS8 MSG tools to drive retrieval and keep queue hygiene high during net operations.

Expected UI behavior:

  • Timed refresh: File-source scans follow Scan Every interval; JS8 message refresh runs on its own shorter cadence.
  • Selection controls: Header select-all checkbox is enabled only in filtered/search states.
  • Delete safety: Bulk and per-row deletes always prompt with scope/result feedback.
  1. Scan every: Dropdown for 1/15/30/60 minutes; controls file folder rescan intervals. JS8Call messages refresh automatically on a short interval.
  2. Refresh Now: Forces an immediate refresh of file-based messages and JS8 inbox data.
  3. Export to PDF: Exports the currently viewed message from the viewer pane.
  4. Pending JS8 MSGs: Shows pending message IDs and actions. Get sends a JS8 QUERY MSG to the callsign; Mark Retrieved clears the pending entry (and can mark JS8 inbox rows READ if enabled in Settings).
  5. Filters row: MSG Type, Status, From, To dropdowns plus free-text Search and Clear Filters. From/To fields are searchable; typing replaces the hint and narrows matches. Status includes Action Needed when red flags exist.
  6. Messages table: Columns are MSG Type, Status, From, To, RCV_DT (UTC), Message Title, Actions. Actions show View for all rows; a flag icon (between View/Delete) for all rows; and Delete for JS8/VarAC/file-based entries and Spotter (F!###) messages.
  7. Flags: Click the flag icon to cycle None -> Red -> Green -> None. Red flags indicate follow-up needed and are included in the Status filter as Action Needed.
  8. Sorting: Click headers to sort by MSG Type, Status, From, To, RCV_DT, or Message Title (Actions is not sortable).
  9. Reader panel: The lower pane shows the selected message and remains open while you review entries.
  10. Loading indicator: A “Brewing it fresh...” message appears to the right of the Messages tab title while data refresh is running, and disappears when refresh completes.
  11. Time display: All message timestamps are displayed in UTC for consistency across message sources.

Notifications and prompts:

  • Send MSG: When clicking Get in Pending JS8 MSGs, a confirmation dialog shows the exact QUERY MSG string before sending.
  • Missing Callsign: If your callsign is not configured, a warning appears when attempting to send a QUERY MSG.
  • Delete Selected: Deletes only checked rows. The button highlights only when at least one row is checked. The confirmation includes counts by message type and the results report Deleted/Skipped/Failed.
  • Row selection: Use the checkbox column to select rows. The header checkbox is a master select/deselect for the current filtered view and is enabled only when a filter or search term is active.
  • Delete File: File-based messages prompt Move this file to the Recycle Bin? and show size/modified time. Failure shows Failed to move file to the Recycle Bin.
  • Delete Message: JS8 deletions show Message {ID} Deleted or Failed to delete Message {ID}. VarAC deletions confirm with Delete VarAC message {ID}? and then show the same success/failure toast.
  • Delete Spotter: Spotter (F!###) messages are deleted from the local spotter_traffic table after confirmation.

FLDigi NCS Tab

Purpose: Manage FLDigi net check-ins and logs.

Typical workflow: Pick role and net name, QSY if needed, start net, collect check-ins into Main/New-Late, save/merge as needed, then end net to persist and import results.

Expected UI behavior:

  • Net lifecycle gating: Start/End/Save workflows follow net-in-progress state and prompt when required fields are missing.
  • Schedule interaction: QSY pauses scheduler enforcement until resumed; scheduled transitions can auto-end active net when applicable.
  • Lookup ergonomics: Operator lookup and Add-to-panel controls support keyboard-centric net operations.
  1. Header clocks: UTC and Local update live at the top.
  2. Next Scheduled Net: Banner shows the next scheduled net; also reflects scheduler pause state.
  3. Role: Dropdown with NCS/ANCS/JOINER; the role is appended to your own line when the net starts.
  4. Net Name: Editable dropdown with schedule-driven suggestions.
  5. QSY controls: QSY dropdown (Operating Groups) and QSY button. QSY changes frequency immediately and pauses schedule enforcement until you click Resume Schedule.
  6. Ad Hoc Net: Generates a UTC-stamped net name and starts the net.
  7. Operator Lookup/Add: Search field that auto-fills known operators. Tab/Enter cycles through Add buttons; active button highlights for keyboard flow.
  8. Add to Main / Add to New/Late: Inserts the lookup line into the corresponding panel.
  9. Compare NCS Lists: Opens a dialog with Compare, Copy Missing, and Close to reconcile your list against an NCS list.
  10. Copy: Copies the full Main or New/Late text to the clipboard.
  11. Main Check-in Log: Editable text area for primary check-ins.
  12. New/Late Check-ins: Editable text area for late or follow-up entries.
  13. Start Net: Clears files, writes your operator line, and begins the net session.
  14. Save Check-ins: Writes both panes to the configured check-in files.
  15. Merge Check-ins: Moves New/Late entries into Main and clears New/Late.
  16. End Net: Saves, imports check-ins into Operator History, and ends the net. Can auto-end if a scheduled frequency change occurs and the scheduler is not paused.

Notifications and prompts:

  • Missing Net Name: Enter Net Name before starting the net.
  • File Error: If check-in files cannot be created or accessed.
  • Net In Progress: When starting an Ad Hoc net while another net is active.
  • Replace Net Name: Confirmation before replacing a typed net name with an Ad Hoc name.
  • Saved: Check-in logs saved.
  • End Net: Confirmation dialog; if the main file is empty, an additional prompt asks to end without importing check-ins.
  • Net Ended: Either reports the number of imported check-ins or that no valid check-ins were found.
  • Compare NCS Lists: Full Match or No missing entries to copy. when appropriate.
  • QSY: Warnings for missing selection or scheduler unavailable; success message indicates the schedule is paused until resumed.
  • Scheduling resumed: Informational message when a paused schedule resumes.

JS8 NCS Tab

Purpose: Manage JS8Call net check-ins, ACKs, and spotter forms.

Typical workflow: Set group and optional expected form, start net, monitor check-ins by filter, ACK/query as needed, save check-ins, then end net and optionally transmit concluded message.

Expected UI behavior:

  • Pre-start requirements: Callsign, net name, and group prerequisites are enforced before start.
  • Action scoping: ACK/query actions apply to group or selected callsign as labeled.
  • Delete gating: Delete action appears only in allowed mode/filter states to prevent accidental check-in loss.
  1. Header clocks: UTC and Local update live at the top.
  2. Role: Dropdown with NCS/ANCS.
  3. Net Name: Text field with schedule-based auto-complete. Auto-prefills when a scheduled net is within the next 20 minutes of its early-check-in time.
  4. Refresh (sec): Polling interval for JS8 (5-300 seconds).
  5. Set Group: Button plus group field (use @GROUP format). Required to start a net.
  6. Set Expect Query: Button plus Spotter dropdown (F!###). The dropdown is disabled if no forms are found.
  7. QSY controls: QSY dropdown (Operating Groups) and QSY button. QSY pauses the scheduler until you click Resume Schedule.
  8. Ad Hoc Net: Starts a net with a timestamped name.
  9. Check-in Filter: Dropdown with F!103 / F!104, Any Spotter, and All Callsigns.
  10. Check-ins table: Columns are CALLSIGN, NAME, ST, GRID, REGION, MODE, SNR, OFFSET, STATUS, and Actions.
  11. Delete action: The Actions column shows Delete only when a net is in progress and the filter is All Callsigns.
  12. Start Net: Clears and begins monitoring.
  13. ACK GROUP / ACK CALLSIGN: Sends acknowledgments to all NEW check-ins or the selected callsign.
  14. E? GROUP / E? Callsign: Sends a spotter form query to the group or selected callsign.
  15. Save Checkins: Saves this net's check-ins to the DB and updates Operators.
  16. End Net: Ends the net and writes a net log file in a net_logs folder next to DIRECTED.TXT.

Notifications and prompts:

  • Missing Net Name: Enter Net Name before starting the net.
  • Missing Callsign: Configure your callsign in the Settings tab.
  • DIRECTED.TXT Not Configured: Prompts to set JS8Call DIRECTED.TXT in Settings.
  • Group Required: Set Call Group to Start Net.
  • Net In Progress: When starting an Ad Hoc net while another net is active.
  • Replace Net Name: Confirmation before replacing a typed net name with an Ad Hoc name.
  • End Net: Dialog TX NET CONCLUDED MSG? with YES / NO / END w/o TX. YES transmits a NET CONCLUDED message to the group.
  • Net Ended: JS8Call net ended and log saved.
  • Spotter: Warnings for missing forms, missing group, or missing callsign; confirmations for Send this JS8Call message?
  • ACK: Info messages for missing net, no NEW check-ins, or no callsigns; confirmation dialog SEND ACK?
  • Saved: Check-ins recorded for this net.

Operators Tab

Purpose: Maintain operator records used by maps and nets.

Typical workflow: Import CSV, normalize roles, bulk-edit Trusted/Role where needed, then export by group for peer or field use.

Expected UI behavior:

  • Bulk select guardrail: Header checkbox enables only when filter/search is active.
  • Role normalization: Group Role values are constrained to the standardized list (plus blank).
  • Export-group multi-select: Group checkmarks persist while popup is open; header text updates to selected count.
  • Theme readability: In dark theme, export-group check indicators use explicit contrast styling.
  1. Search: Text box that filters by any column (case-insensitive).
  2. Filter by: Dropdown with All, Untrusted, Blank, and any discovered group names. Use it to scope the table and exports.
  3. Manage Operators: Menu with Add Operator..., Edit Selected... (bulk trusted + bulk group role update), and Delete Selected.... Selection is via the checkbox column.
  4. Bulk select: The header checkbox selects/deselects all visible rows in the current filtered view. It is enabled only when a filter or search term is active.
  5. Export by Group: Checkbox dropdown. The header shows Export by Group or N Selected. The first row says Select groups... (not checkable). You can select any number of groups; selections are cleared after a successful export.
  6. Export by Group selection behavior: Click group rows to toggle checkmarks. On Linux and Windows, checked items should remain selected and the header should update to N Selected.
  7. Import/Export...: Menu with Import CSV... and Export CSV....
  8. Operators table: Columns are Select (checkbox), Callsign, Name, State, Grid, Groups (summary), Group Role, First Seen, Last Seen, Trusted, Check-ins. Group 1/2/3 are stored but hidden by default.
  9. Edit Groups: Double-click the Groups column to edit the full group list for that callsign (one group per line).
  10. Bulk edit/delete summaries: Bulk trust edits and deletes show summary counts (Updated/Deleted, Skipped, Failed).
  11. Loading indicator: A “Brewing it fresh...” message appears to the right of the Operators tab title while data refresh is running, and disappears when refresh completes.
  12. Add/Edit dialog fields: Callsign, Name, State, Grid, Group 1/2/3, Group Role, First Seen, Last Seen, Trusted ("do I trust their reports?"). Group Role is standardized to blank, HUB, HUB-ALT, NCS, ANCS, or PEER.

Export behavior:

  • Required selection: Export requires selecting one or more groups in the Export by Group dropdown.
  • Filtering: Export uses the current filter/search and/or selected rows; only trusted records with at least one group are exported.
  • Groups column: The exported groups field contains only the selected groups that are actually associated with each callsign (row-specific intersection).
  • Filename: Defaults to CALLSIGN_group1_group2_group3_yyyymmdd.csv using the selected groups.

Notifications and prompts:

  • Export CSV: Prompts to select one or more groups before exporting; shows No rows to export if nothing matches.
  • Export by Group visual checkmarks: In dark theme, check indicators in the export-group popup are rendered with explicit contrast styling for readability.
  • CSV Import: Success and error messages report imported/skipped counts or failures.
  • Delete Selected: Confirmation required before deleting operator records.

Typical workflow: Start broad (All paths / Any recency), then narrow by group, region, band, and recency until only actionable paths remain. When you want propagation guidance, enable the propagation overlay and pick a mode.

Expected UI behavior:

  • Refresh semantics: Refresh Links forces ingest/redraw cycle using current filters.
  1. Map link controls row: Paths (Off/My Station/All), Group, Region, Band, Recency (Any, 15m, 30m, 1h, 3h, 6h, 12h, 24h, 7d), Paths to (editable callsign), and Refresh Links.
  2. Map Layers (sidebar): Only visible when Map is active. Checkboxes for Callsigns, States, Cities, Grids, Regions plus a City Pop. dropdown.
  3. Propagation controls: Propagation Overlay toggle, Mode selector (Actual / Blended / Modeled), and Propagation Window.
  4. Paths to: Filters link highlights to paths that reach a specific callsign.
  5. Refresh Links: Forces JS8 log ingest and redraw.
  6. Map view: Requires Qt WebEngine; if unavailable, a disabled message is shown instead of the map.
  7. Tooltips: Station tooltips include JS8 and VarAC fields when data exists: JS8 Last Seen, JS8 Spotter, JS8 Last Band, JS8 Direct SNR (and traffic count), JS8 Avg SNR (and traffic count), VarAC Last Seen, VarAC Last Band, VarAC SNR.

Propagation Overlay (New)

Purpose: Show the best probable band from your station to each region/state based on the selected mode, time-of-day, and available observed data.

  • Overlay activation: Turn on Propagation Overlay in the Map Layers box to color the map by recommended band.
  • Mode selection: Choose Actual, Blended, or Modeled for how the recommendation is computed.
  • Propagation Window: Controls how far back observed traffic is considered for Actual/Blended. Modeled ignores this window.
  • Band colors: Band colors are pulled from your FreqPlanner band color palette.

Mode meanings (Actual / Blended / Modeled)

  • Actual: Ignores the propagation model and uses observed data only (JS8/VarAC link history + peer schedules). This is the most literal view of where stations were and what bands they were actually using.
  • Blended: Combines the propagation model with observed data. Use this when you want real-world evidence to temper model predictions.
  • Modeled: Uses the offline propagation model only. This is best when you have limited recent traffic or want a baseline prediction.

Propagation Window

Purpose: Define how much recent traffic informs the Actual and Blended modes.

  • Options: 1h, 3h, 6h, 12h, 24h, or History (7d).
  • Recency vs propagation: Recency filters the visible map links; Propagation Window controls the actual/observed weighting for the overlay. They are independent.

How to read the overlay

  • State colors: When propagation is enabled and Regions are off, each state is colored by its best band for your station.
  • Region colors: When Regions are on, regions keep their regional color. The recommended band for each region appears as a band label beneath the region label.
  • Tooltips: Labels show Band (LOW/MED/HIGH) confidence. Lower confidence suggests marginal propagation or sparse observation.
  • Best Now summary: The Propagation badge shows a short summary (Filter / Best Now / Schedule) for quick validation.

Novice workflow

  1. Enable Propagation Overlay.
  2. Select Blended for balanced guidance.
  3. Choose a Propagation Window of 6h or 12h.
  4. Pick a Region filter to focus on your target area.
  5. Use the colored state/region guidance to decide which band to check first.

Expert notes

  • Distance + day/night behavior: Modeled uses distance class (NVIS / regional / long-path) and local day/night weighting based on midpoint time between you and the target.
  • Grid accuracy matters: Operator Grid 6 fields directly influence distance and weighting. Missing/incorrect grids degrade predictions.
  • Peer schedules vs traffic: Peer schedules are treated as observed intent. Actual/Blended mode will weight them within the Propagation Window.
  • Use Modeled for planning: If you are planning for expected conditions rather than recent activity, Modeled gives you a clean baseline.

Troubleshooting tips:

  • Overlay looks empty: Ensure your own Grid 6 is set in Settings and the Propagation Overlay is enabled.
  • Unexpected band choice: Try Modeled to compare, then Blended to see how recent activity changes the result.
  • No observed impact: Confirm JS8 Traffic load has run and that peer schedules have been imported.

HF Schedule Tab

Purpose: Plan routine operating blocks.

Typical workflow: Define recurring operating windows by group/frequency, save, confirm in FreqPlanner, and use QSY for ad hoc moves that intentionally pause enforcement.

Expected UI behavior:

  • Validation on save: Invalid time/frequency rows are skipped with explicit feedback.
  • Display conversion: Local view converts to UTC on save; underlying storage remains UTC.
  • Delete emphasis: Delete Selected highlights when row checkboxes are active.
  1. Header clocks: UTC and Local update live.
  2. Showing: UTC/Local: Toggle the time display only. When in Local view, times are converted to UTC on save.
  3. QSY controls: QSY dropdown (Operating Groups) and QSY button. QSY applies frequency immediately and pauses the scheduler until resumed.
  4. Schedule table: Columns are Select, Day, Group Name, Mode, Band, Freq (MHz), Start, End, Auto-Tune. The table is not sortable.
  5. Add Row: Inserts a new schedule row.
  6. Delete Selected: Removes checked rows. The button highlights only when at least one row is checked.
  7. Save HF Schedule: Saves to the database and refreshes FreqPlanner.
  8. Export HF Schedule: Exports JSON in UTC with your callsign and date in the filename.

Validation and formatting:

  • Time format: Start/End must be HH:MM (24-hour). Invalid rows are skipped and reported.
  • Frequency required: Every row must have a frequency.
  • Band limits: Frequencies are validated against band/mode ranges; 60M accepts only the standard channels.

Notifications and prompts:

  • Partial Save: Lists skipped rows (invalid times).
  • Save Failed / DB Save Error: Shown if saving to settings or DB fails.
  • Saved: HF Frequency Schedule saved.
  • Export: No HF schedule rows to export. or HF schedule exported to: ...
  • QSY: Warnings for missing selection or scheduler unavailable; success message indicates the schedule is paused until resumed.
  • Scheduling resumed: Informational message when a paused schedule resumes.

Net Schedule Tab

Purpose: Define net windows and how they repeat.

Typical workflow: Build net windows with recurrence + early-check-in rules, validate net names and times, save, then verify expected start/end behavior in FreqPlanner and NCS tabs.

Expected UI behavior:

  • Recurrence coupling: Recurrence choice drives Day/Weeks field behavior (enable/disable/required).
  • Early-check-in rules: Early minutes expand start window for net activation and NCS readiness.
  • Import/export fidelity: JSON import/export uses UTC schedule semantics consistently.
  1. Header clocks: UTC and Local update live.
  2. Showing: UTC/Local: Toggle the Day/Start/End display only. When in Local view, Day/Start/End are converted to UTC on save (including Daily/ALL rows).
  3. Schedule table: Columns are Select, Day (UTC/Local), Recurrence, Weeks of Month, Group Name, Mode, Band, Freq (MHz), Start, End, Early (min), Net Name, Auto-Tune. The table is not sortable.
  4. Recurrence: Weekly, Daily, or Periodic. Daily forces Day=ALL and disables the Day field. Periodic disables ALL and requires a specific day.
  5. Weeks of Month: Enabled only for Periodic. Accepts digits 1-5 and auto-formats to comma-delimited values (e.g., 135 -> 1,3,5).
  6. Add Row: Inserts a new schedule row.
  7. Delete Selected: Removes checked rows.
  8. Export Net Schedule: Exports JSON in UTC.
  9. Import Net Schedule: Imports JSON (interpreted as UTC).
  10. Save Net Schedule: Saves to the database and refreshes FreqPlanner.

Validation and formatting:

  • Day required: Every row must specify a day; Periodic cannot use ALL.
  • Net Name required: Net Name must be filled before saving.
  • Frequency required: Validated against band/mode ranges; 60M must use the standard channels.
  • Time format: Start/End must be HH:MM (24-hour).
  • Early check-in: Must be 0, 5, 10, or 15.

Notifications and prompts:

  • Invalid Net Schedule: Shows the exact row error when validation fails.
  • Saved: Net Schedule saved.
  • Export: No net schedule rows to export. or Net schedule exported to: ...
  • Import Failed / Invalid File / No valid rows: Shown when import JSON is missing keys or invalid.
  • Imported: Imported N net schedule rows.

Peer Schedules Tab

Purpose: Track schedules imported from other operators.

Typical workflow: Import peer files, filter by callsign/region/group, review overlap summaries, and use overlap details to plan coordination windows.

Expected UI behavior:

  • Overlap interaction: Overlap cells with values are clickable to open detailed intervals.
  • Local display toggle: Show Local affects rendered columns only; imported data remains UTC-native.
  • Scoped deletion: Delete controls support single-peer or clear-all workflows with confirmation.
  1. Import Schedule: Loads a peer HF schedule JSON (UTC).
  2. Refresh: Reloads the list from the database.
  3. Delete: Dropdown for callsigns plus Delete Schedule to remove a single peer schedule. The dropdown also includes Clear All Schedules.
  4. Show Local: Toggle to display DAY/START/END/OVERLAP in local time; headers show your local TZ abbreviation in parentheses.
  5. Filters: Callsign dropdown, Region dropdown (R01-R10), Group dropdown, and Search field.
  6. Overlap: Shows upcoming overlaps for today only (UTC day) where your HF and Net schedules share the same frequency and mode with the peer schedule. Multiple overlaps show a count (e.g., 3 overlaps); click the cell to view details.
  7. Peer schedule table: Columns are CALLSIGN, NAME, STATE, GROUPS, DAY (UTC), START UTC, END UTC, BAND, MODE, FREQ, OVERLAP. The table is not sortable.

Notifications and prompts:

  • Overlap Details: Clicking the Overlap cell opens a details dialog with each HH:MM-HH:MM overlap.
  • Import Failed / Invalid File / No valid rows: Shown when import JSON is missing keys or invalid.
  • Import: Imported N rows for CALLSIGN.
  • Delete: Confirmation dialog for delete or clear-all; success or failure messages after DB writes.

Settings Tab

Purpose: Configure operator details, scheduler behavior, and integrations.

Typical workflow: Configure identity and control mode first, then operating groups, then JS8/radio paths, then scheduler enforcement behavior, and finally save/test.

Expected UI behavior:

  • Collapsible sections: Expanding one integration section may collapse others for focus.
  • Save propagation: Saving settings triggers downstream tab refreshes and status recalculation.
  • Theme application: Theme changes apply globally after save/refresh cycle.

Quick links: Operator Information | FreqInOut Settings | Operating Status | Operating Groups | JS8Call Settings | Radio Software | Save Settings

Collapsible sections: Operating Groups, JS8Call Settings, and Radio Software are collapsible. Expanding one collapses the others; collapsed headers show a short summary.

Operator Information

  • Header clocks: UTC and Local update live.
  • Callsign / Name / State / Grid 6: Used in net control, operator history, and map placement.

FreqInOut Settings

  • Theme: Light or Dark.
  • Frequency Control: FLRig, JS8Call, or Manual (no rig commands).
  • Use FreqInOut Scheduler: Master enable for schedule-driven changes; QSY depends on this.
  • Enforcement timers: Frequency, FLDigi Mode, and JS8 Offset each have their own enforcement dial. Default is On Schedule Change. Choosing Prompt enables a per-item interval (Hourly / 5 / 10 / 15 / 30 minutes).
  • Off-schedule prompts: When one or more enabled items first go off schedule, a combined prompt appears listing only the items that are currently off (e.g., Frequency and Offset are Off Schedule). Resume Sched. immediately enforces only the listed items (frequency/mode/offset) and leaves others unchanged. Skip Once dismisses the prompt and resets the timer for those items without applying changes. Pause Sched. 30 Min pauses enforcement for 30 minutes. If unanswered for 2 minutes, the listed items are applied automatically. Repeat prompts follow the selected interval. Using Resume Schedule from the status panel overrides any prior Skip/Pause state.
  • Net handling (scheduled + ad hoc): While any net is active (scheduled or Ad Hoc), automatic corrections are suppressed so the operator stays in control. This includes frequency, FLDigi mode/offset, and JS8 offset. At net start, the scheduler may apply the net’s FLDigi mode/offset once (a short initial window) to land you on the net settings; after that, changes you make during the net are left alone. At net end, the scheduler clears any pending/backoff state and immediately resumes the active schedule (frequency + FLDigi mode/offset + JS8 offset) unless scheduling is paused or in Manual control.
  • Activity check: Before any scheduled frequency change, the scheduler checks for active transmissions and recent receive activity. It skips changes if FLRig PTT is active, JS8Call PTT is active, JS8 RX activity occurred in the last ~12 seconds, or VarAC reports busy. It also checks FLDigi RX activity from the FLDigi log and delays schedule changes while recent valid traffic is being received (not used during scheduled or ad hoc nets). HF schedule frequency changes will wait up to ~10 minutes for FLDigi RX activity before proceeding. FLDigi busy detection includes a gibberish-aware grace and a timeout so noisy bursts don’t hold the schedule indefinitely.
  • VarAC busy detection: VarAC activity is read from VarAC_traffic.log in the VarAC install folder. Busy conditions include “WAITING FOR FREQUENCY TO CLEAR,” active connections, incoming connection requests, file transfers or “waiting for confirmation of receipt,” and incomplete broadcasts (a broadcast line without a trailing “-” within ~12 seconds). VMAIL relay notifications and your own beacon lines (ending with DE YOURCALLSIGN) are ignored.
  • Wait behavior: There is no fixed delay timer. Changes resume as soon as the activity checks clear (PTT off, JS8 RX window elapsed, VarAC disconnected). Manual QSY pauses schedule enforcement until you click Resume Schedule.

Operating Status

  • Status LEDs: JS8 (API reachability), FLRig, FLDigi, FLMsg, FLAmp, VarAC, JS8Spotter, CommStat.
  • Color meaning: Green running, gray stopped, yellow running but unreachable.

Operating Groups

  • Add Group: Opens a dialog to define Group Name, Mode, Band, Frequency, VFO, FLDigi Starting Mode, FLDigi Starting Offset (Hz), and Auto-Tune.
  • Edit Selected: Edits the checked row (one at a time).
  • Delete Selected: Removes checked rows.
  • Operating Groups table: Columns are Selected, Group, Mode, Band, Freq (MHz), VFO, FLDigi Starting Mode, FLDigi Starting Offset, Auto-Tune.
  • Defaults: If Mode is set to SSB, FLDigi Starting Mode is automatically set to SSB.

Operating Groups validations:

  • Group Name required: Missing name shows a validation warning.
  • Frequency validation: Invalid numbers or out-of-band values show warnings.
  • FLDigi Starting Offset: Must be an integer.

JS8Call Settings

  • TCP Port: Must match JS8Call configuration.
  • Offset (Hz): Applied on startup and on schedule changes.
  • Mark JS8Call MSG Read?: Syncs Message Viewer Mark Retrieved to JS8Call inbox READ state.
  • JS8Call DIRECTED.TXT: Path field plus Browse button.
  • JS8Spotter forms: Path field plus Browse button (MCF###.txt files).
  • Load JS8 Traffic: Ingests DIRECTED.TXT/ALL.TXT into Map and Operators.

JS8Call notifications:

  • Missing path: Please set JS8Call DIRECTED.TXT path first.
  • File not found: DIRECTED.TXT not found at: ...
  • JS8 Traffic Loaded: Success message after ingest.
  • Error: Ingest failures show the underlying error.

Radio Software

  • Program rows: FLRig, FLDigi, FLMsg, FLAmp each have a checkbox (for Launch Selected), path field, and Browse button.
  • FLRig XMLRPC Port: Port field under the FLRig row.
  • Check-in File Path: FLDigi check-in folder plus Browse.
  • ICS/Messages: FLMsg folder plus Browse.
  • FLAMP/rx: FLAmp folder plus Browse.
  • VarAC: Browse to the VarAC install folder. FreqInOut uses this path to locate VarAC.db and VarAC_traffic.log. Also set the VarAC Incoming Files path for file-based messages.
  • FLDigi Log Path: Select the folder that contains FLDigi log files (e.g., fldigiYYYYMMDD.log). The newest log in that folder is used to detect recent RX activity.
  • Enable FLDigi logging: FLDigi RX/TX monitoring depends on logging. In FLDigi, enable File > Text Capture > Log all RX/TX text.
  • Launch Selected: Launches checked programs that are not already running. JS8Call is not launched from here.
  • Check-in Log Paths: Copy Main and Copy New/Late buttons copy full file paths to the clipboard.

Radio Software notifications:

  • Launch: If no programs are selected, a message indicates that nothing was launched.
  • Invalid Path: Warning when a selected file path does not exist.
  • Copied: Copy buttons confirm the copied path.

Save Settings

  • Save Settings: Persists all settings and refreshes dependent tabs. A confirmation dialog appears: Settings saved.
  • Auto-save on exit: Settings are also saved when the app closes.
  • Theme change: Switching Light/Dark shows Wilco. Standby for Spectrum QSY... until the new theme is applied.

Troubleshooting and Tips

Purpose: Common fixes and operational tips.

  • Scheduler not changing frequency: Verify Use FreqInOut Scheduler is on, the pause timer has expired, and Operating Groups include valid band/mode/frequency.
  • JS8 NCS will not start: Check that callsign, Net Name, Group, and DIRECTED.TXT are set in Settings.
  • Messages list is empty: Confirm Message Paths in Settings and click Refresh Now.
  • Map shows no links: Use Load JS8 Traffic in Settings and confirm DIRECTED.TXT is valid.
  • Logs too large: Keep level at DISABLED or INFO for daily use; raise to DEBUG or ALL only for troubleshooting.

Background Timers Reference

Purpose: Quick reference for the most important recurring timers and time windows in FreqInOut.

  • Scheduler engine poll: Re-evaluates active schedule and enforcement decisions on a repeating interval.
  • Off-schedule prompt timeout: Auto-applies listed corrections after 2 minutes if no response.
  • Status panel refresh: Main-window status indicators refresh on a short recurring cycle.
  • SOP due windows: Due/overdue visibility follows SOP state timing rules and active SOP filters.
  • Messages scan timer: File-message refresh follows Scan Every interval; manual refresh is always available.
  • JS8 NCS refresh timer: JS8 NCS tab uses configured polling interval (seconds) for ingest/update cadence.
  • Prompt interval timers: Scheduler prompt cadence for frequency/mode/offset follows configured prompt interval policy.

Known Platform Differences (Windows vs Linux)

Purpose: Help operators distinguish expected platform behavior from actual defects.

  • Desktop launcher trust (Linux): Some desktop environments (notably Mint/Cinnamon) may require one-time launcher trust/allow-launching after icon creation.
  • Desktop icon cache timing (Linux): Icon/menu updates may appear after cache refresh, logout/login, or reboot depending on desktop environment.
  • Combo/list checkbox rendering: Checkbox appearance and click behavior in popup lists can vary by Qt style/theme; FreqInOut applies explicit styling for critical controls in dark mode.
  • Path conventions: Windows uses drive-letter paths; Linux uses POSIX paths. Misconfigured integration paths are a common root cause for missing data.
  • Process detection semantics: Running-process checks and launcher behavior differ slightly by OS session model; always verify via Logs tab if behavior seems inconsistent.
  • Packaged vs source environment: Startup/runtime behavior can differ when running packaged executables vs source/venv workflows; confirm your mode before troubleshooting.

Database Tools

Purpose: Inspect or clean the SQLite databases used by FreqInOut.

  • freqinout_db.py + wrappers: Cross-platform DB wrapper with shell launchers.
  • db_tools.py: Simple CLI to list, show, export, and truncate tables.
  • db_admin.py: Admin CLI to initialize or truncate full tables (settings + nets).
  • js8_links_check.py: Quick inspection of JS8 link ingestion.
  • dedupe_operator_groups.py: Cleanup tool for legacy duplicate group assignments in operator records.
  • Database locations: Settings live in config/freqinout.db. Operator and net data live in config/freqinout_nets.db.

Command examples (copy/paste):

python tools/freqinout_db.py status
bash tools/freqinout-db.sh status
powershell -ExecutionPolicy Bypass -File .\tools\freqinout-db.ps1 status
python tools/db_tools.py --list-dbs
python tools/db_tools.py --table operator_checkins --table-show
python tools/db_admin.py --init all
python tools/db_admin.py --truncate nets_all --yes
python tools/js8_links_check.py --limit 20
python tools/dedupe_operator_groups.py
python tools/dedupe_operator_groups.py --apply
